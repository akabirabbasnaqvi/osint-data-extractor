# Contributing

Thanks for contributing. This project handles public-information research, so all changes must preserve legal, privacy, and safety safeguards.

## Before opening a pull request

1. Create a focused branch from `main`.
2. Keep secrets, `.env` files, personal data, and scraped results out of commits.
3. Add or update tests for behaviour changes.
4. Update the README or configuration documentation when relevant.
5. Use clear commits such as `feat: add company-result validation`.

## Pull request expectations

Describe the problem, the solution, test coverage, and any privacy/security impact. Keep pull requests focused; do not combine unrelated refactors and features.

## Collector rules

Do not add functionality that bypasses authentication, CAPTCHAs, paywalls, or access controls. Respect applicable law, provider terms, and reasonable rate limits.

## Reporting bugs and security issues

Use the issue templates for ordinary bugs and feature ideas. Read `SECURITY.md` for private security reports.
