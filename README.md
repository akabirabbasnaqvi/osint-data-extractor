# Public Intelligence — OSINT Aggregation SaaS

A web application that searches public sources (Google/DuckDuckGo, LinkedIn, GitHub,
Twitter/X, Facebook, Instagram, etc.) for information about a person and returns a
consolidated profile. Built entirely on free/open-source tooling.

Reference: `Public Intelligence SaaS_blueprint.pdf` (project blueprint, v1.0).

## Stack

- **Frontend:** Next.js 14 + Tailwind + shadcn/ui
- **Backend API:** FastAPI (Python 3.11.8)
- **Task Queue:** Celery + Redis
- **Database:** PostgreSQL 16
- **Scraping:** Scrapy + Playwright + BeautifulSoup4

## Project Status

This repository contains a functional local-development prototype: a Next.js
interface, FastAPI API, Celery worker, PostgreSQL data model, and public-source
collection tasks. It is not production-ready; see the privacy and deployment notes
below before exposing it to the internet.

## Local Development (you run these yourself)

1. Copy `.env.example` to `.env` and fill in values.
2. `docker compose up -d --build` — starts Postgres, Redis, SearxNG, runs the
   database migration, then starts the API and worker.
3. Backend API available at `http://localhost:8000`
4. API docs (auto-generated by FastAPI) at `http://localhost:8000/docs`

SearxNG is deliberately available only to the Docker services. The backend uses it
internally; it is not published to your computer or the public internet.

## Discovery (finding profile URLs, emails on other public pages, etc.)

This uses a self-hosted **SearxNG** instance (the `searxng` service in
`docker-compose.yml`) — a free, open-source metasearch engine. No API key, no
billing account, no card required. This is the actual ceiling of "100% free,
no account" web search — every real API alternative tried (Google Custom
Search, Brave Search) turned out to require a payment method on file even for
its nominally free tier.

**Treat this as best-effort, not guaranteed.** The search engines SearxNG
queries (DuckDuckGo, Brave, Startpage, Bing, Google) actively detect and
block/rate-limit automated traffic, so discovery will sometimes come back
empty or partial — that's expected behavior for free scraping-based search,
not a bug. GitHub lookups and anything you provide directly (name, LinkedIn
URL, etc.) always work regardless of whether discovery finds anything.
